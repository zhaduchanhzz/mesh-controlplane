## Mục tiêu

1. **Placement tự động** cho tailnet mới trên ≥ 2 cluster: cùng lớp shard, chỉ cluster `ACTIVE` còn chỗ, phân tán được khi tải thiết bị bằng nhau (luật theo Q1), không chọn cluster không có process giữ lease (nếu Q2 = có). Mọi đường tạo/chuyển tailnet (API `mesh-placement` và CLI, theo Q5) dùng cùng luật của `placement.Registry`.
2. **Reconcile giữa cluster:** báo cáo chỉ đọc cho operator các bất thường R1–R9 (inventory §3.2): tailnet do cluster chưa đăng ký / `DISABLED` / không có lease sống sở hữu, endpoint hoặc Noise key lệch registry, cluster vượt `max_devices`, dedicated có hơn một tailnet, tailnet `PENDING` lâu. Không tự động chuyển tailnet (Q4).
3. **Bootstrap trả đúng cluster** cho mọi tailnet được placement đặt, ngay sau activate và sau `MoveOwner`; cluster không sở hữu từ chối (F07).
4. **Nghiệm thu PLAN:** 3 tailnet / 2 cluster tạo qua placement, client thật; restart và failover active → standby **trên cả hai cluster**; không owner kép (I12), không lộ chéo tenant.

## Thứ tự (RED trước)

1. RED placement (SQLite + PostgreSQL): tailnet mới phân tán khi tải bằng nhau (hiện 3/0); bỏ cluster không có lease sống; CLI/`reassign` tuân luật `Registry`. → sửa `place`, CLI.
2. RED báo cáo reconcile: mỗi R1–R9 một ca → đúng một mục; dữ liệu sạch → rỗng; chỉ trả ID/số đếm. → `Registry` + `GET /v1/reconcile` (tên tạm) trên API operator mTLS; spec qua generator (AGENTS 10).
3. RED servertest **hai cluster ID trên cùng DB**: owner đúng nạp tailnet mới, cluster kia không bao giờ; `MoveOwner` → nguồn retire, đích nạp, ghi của nguồn `ErrFenced`; đo cửa sổ R11; 3 tailnet / 2 cluster không peer/IP/node chéo; failover trong một cluster không ảnh hưởng cluster kia.
4. Phía cluster theo Q3/Q6 (`clusters.state`, đối chiếu Noise public key khi lấy lease), mỗi thay đổi có RED.
5. Lab (sau duyệt Q8): standby c2, front door `/ready` cho c2, `mesh-placement` trên lab.
6. E2E mở rộng `infra/lab/e2e/twocluster/run.sh` (chờ `/ready`): tạo 3 tailnet qua `mesh-placement`, bootstrap đúng cluster, restart c1 và c2, failover trên c1 và c2 (mức theo Q9), báo cáo reconcile sạch, audit `owner_epoch` + `cluster_leases`, artifact không secret; ×2, client v1.104.7 và v1.84.3.
7. Evidence `evidence/P12-*.md` theo mẫu AGENTS; cập nhật PLAN.

## Bằng chứng nghiệm thu

- Lệnh test + exit code (unit/race SQLite + PostgreSQL trên mc-ci, servertest).
- E2E hai lần PASS, artifact đã redact; bảng tailnet → cluster → URL bootstrap; thời gian failover mỗi cluster; số node/IP trước/sau failover (không đăng nhập lại).
