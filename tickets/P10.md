# P10 — Registry và placement trên PostgreSQL dùng chung, fencing owner/epoch

- **Trạng thái:** `Planned`
- **Nhánh:** `feat/P10-placement-fencing`
- **Inventory:** `evidence/source-inventory-P10.md`
- **ADR:** [0005](../design/adr/0005-cluster-architecture-shared-postgres-bootstrap-incremental-netmap.md) (Bổ sung mục 4, Bổ sung 2 §2–§3), [0003](../design/adr/0003-shard-classes-and-tenant-migration.md)

## Mục tiêu

1. **Registry nằm trong PostgreSQL dùng chung**, không phải DB riêng: bảng `clusters` (endpoint URL, lớp shard, trạng thái, public key Noise để đối chiếu) và cột `owner_cluster_id`, `owner_epoch` trên `tailnets` (cột đã có từ P03b).
2. **Fencing trong mọi mutation:** mọi ghi dữ liệu tenant kiểm `owner_cluster_id` = cluster của process và `owner_epoch` = epoch process đang giữ, **trong cùng transaction** (I12). Sai → rollback, runtime của tenant tự dừng.
3. **Placement:** `internal/placement` chọn cluster khi tạo tailnet theo lớp shard (*shared*/*dedicated*) và quota; đếm thiết bị theo tenant; hard quota 5.000 trên *shared* (từ chối enrollment fail closed), cảnh báo 80%.
4. **API operator** `cmd/mesh-placement`: `CreateTailnet` (một transaction theo PLAN §5), `ActivateTailnet`, `SuspendTailnet`, `GetTailnet`, `ListClusters`, `UpdateClusterState`. mTLS + platform operator + idempotency + audit. (mTLS cho API nội bộ chuyển từ ticket P11 cũ sang đây.)

Lease cluster và failover active/standby là P11b; P10 chuẩn bị điểm gắn (fencing token có chỗ cho epoch lease).

## Phụ thuộc

- P09 (gate N1), P00c (số đo để đặt quota/ngân sách cluster).
- P03b (schema PostgreSQL dùng chung, cột owner, plugin scope).

## Phạm vi

| Thành phần | Thay đổi |
|---|---|
| Schema | `clusters` đầy đủ; index `tailnets(owner_cluster_id, status)`; đếm thiết bị theo tenant (truy vấn hoặc counter có kiểm) |
| `internal/placement` | Model, CAS trên `owner_epoch`, chọn cluster, quota |
| Lớp DB của cluster | Một helper transaction duy nhất cho mutation tenant: `BEGIN` → kiểm owner/epoch (`SELECT … FOR SHARE`) → mutation → `COMMIT`. Không có đường ghi tenant nào bỏ qua helper; lint/test giống lint SQL thô của P03b |
| Runtime | Khi thấy `owner_cluster_id` ≠ mình hoặc epoch mới hơn: dừng runtime của tenant, đóng stream, không phát MapResponse |
| Operator API | `cmd/mesh-placement`, OpenAPI qua Huma (AGENTS rule 10) |

## Ngoài phạm vi

- Lease cluster, active/standby (P11b). Bootstrap (P11). Cluster thứ hai trong lab (P12). Move (P12b).
- RLS, role DB theo cluster (không làm, ADR 0005 Bổ sung 2 §3).

| Test | Ánh xạ |

## Bằng chứng nghiệm thu

- Unit + race trên `mc-ci` với PostgreSQL; integration hai process cùng DB, khác cluster ID.
- Bảng mọi đường ghi tenant và bằng chứng nó đi qua helper fencing.
- Audit log của CAS; đo overhead của kiểm owner/epoch trên đường ghi (before/after).
- Reviewer bảo mật duyệt fencing (PLAN §10).

## Điều kiện dừng

- Có đường ghi tenant không thể đưa vào cùng transaction với kiểm owner/epoch (ví dụ ghi bất đồng bộ từ batcher): dừng, liệt kê, ADR.
- Overhead fencing làm hot path chậm vượt mức chủ dự án chấp nhận: báo số đo, chờ quyết định. Không bỏ kiểm.
- Bất kỳ owner kép nào: **BLOCK MERGE** (AGENTS rule 13).
